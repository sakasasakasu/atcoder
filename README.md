AtCoderの精進をする過程で気づいたことや反省をまとめています。

今まではNotionでまとめていたのですが、エンジニアっぽさがないのでGithubを使う方針でやろうと思います。

いずれは様々な方法でまとめたいという思いがあります。

## 技術スタック
ReactはUIコンポーネントライブラリが充実しているので簡単に作れるかなと思って、こうしました。

mainブランチにpushされるとGithub ActionsABCディレクトリ以降の情報をパースして内容をjsonに変換するようにしています。

同時にサイトをビルドして静的サイトとしてGithub pagesに公開されます！

## 新しい問題を追加する

`content/problems/ABC/ABC###/`（例: `ABC471`）の新規問題ディレクトリは、手作業でファイルを作らずに CLI で生成できます。

リポジトリ直下（`/atcoder`）で実行します。

```bash
# 基本（README.md を生成）
./new-abc ABC471

# 数字のみでも可
./new-abc 471

# 生成内容のプレビュー（ファイルは作成しない）
./new-abc 471 --dry-run

# 問題セクションを指定（例: A, B, C のみ）
./new-abc 471 --problems ABC

# 感想を入れて生成
./new-abc 471 --summary "今回は2完"

# 解答コードの雛形も生成（デフォルトでは生成しない）
./new-abc 471 --cpp

# 俺が本当に使うもの
./new-abc 471 --cpp --problems ABCD
```

### 生成されるファイル

```
content/problems/ABC/ABC471/
├── README.md        # 問題一覧の元データ。`## A問題` のようなセクションを含む
├── A.cpp            # A問題の解答コード
├── A1.cpp           # （任意）A問題の別解コード
└── B.cpp            # B問題の解答コード
```

`--cpp` を指定した場合は、`--problems` で指定した範囲の `X.cpp` の雛形も生成されます。

### セクションの追加

`content/problems/` 直下の各ディレクトリが「セクション」です。サブディレクトリ（コンテスト形式）または直下の `.cpp`（典型形式）が自動で拾われるため、`ARC/` などを追加するだけで一覧に反映されます。詳しくは [`content/problems/README.md`](content/problems/README.md) を参照してください。

## 解法（solutions/）

問題の解き方のメモは `content/solutions/` ディレクトリに**グループ（ディレクトリ）**ごとに置きます。

```
content/solutions/
├── README.md          # このファイルは解析対象外
└── 典型テクニック/
    ├── ダイクストラ法.md
    └── ダイクストラ法.cpp   # （任意）コードがあるとモーダルで表示
```

- 各グループの `README.md` は解析対象外です。
- ファイル先頭の `# タイトル` は解法のタイトルとして扱われます。
- 本文では `$...$`（インライン）と、`$$` を独立行に置いたブロック数式が LaTeX として使えます。

## Tips（tips/）

短い小ネタ・コツは `content/tips/` ディレクトリにグループごとに置きます（タイル一覧＋クリックでモーダル表示）。

```
content/tips/
├── README.md          # このファイルは解析対象外
└── 典型テクニック/
    └── 二分探索の終了条件.md
```

## 言及（メンション）で問題と解法をリンクする

`.md` 内で `[[対象ID]]` と書くと、生成時に自動でハイパーリンクになり、対象側にタグ（バックリンク）も付きます。`.md` 自体は編集されません。

- 問題 ID: `[[ABC471-A]]` / `[[典型-002]]`（コンテストID-問題ID）
- 解法 ID: `[[ダイクストラ法]]`（ファイル名。グループをまたいで一意にする）

例（解法のメモ内）:

```markdown
# ダイクストラ法

[[ABC471-A]] で初めて使った。
```

- 解法内の `ABC471 A問題` の部分が問題カードへのリンクになり、問題カード側に「解法: ダイクストラ法」タグが付きます。
- 逆に問題の `README.md` 内で `[[ダイクストラ法]]` と書けば、解法カード側にタグが付きます。

## 新しい解法・Tips・ライブラリを追加する

`content/solutions/` / `content/tips/` にグループディレクトリと `.md` を、`content/library/` にカテゴリディレクトリと `.md` を置くだけです。表示には JSON の再生成が必要です。

### オプション

| オプション | 内容 |
|---|---|
| `-p, --problems <文字列>` | 生成する問題セクション（デフォルト: `A-G`）。`A-C` は A,B,C / `A,C` は A,C / `ABC` は A,B,C / `A-G` は A〜G。重複は除去し、A〜G 以外はエラー |
| `-s, --summary <テキスト>` | README の感想欄の初期テキスト |
| `--cpp` | `X.cpp` の雛形も生成 |
| `-d, --dry-run` | ファイルを作成せず、生成予定の内容を表示 |
| `-h, --help` | ヘルプを表示 |

### 注意

- コンテスト ID は `ABC###` または `###`（3桁）の形式のみ受け付けます。実在確認は行いません。
- 既に同じディレクトリ・ファイルが存在する場合はエラーになり、上書きはしません。
- 生成コマンドは Git 操作（add / commit / push）を実行しません。
- 生成後は `npm run dev`（または `npm run build`）を実行すると、`predev` / `prebuild` で `content/problems/` が JSON 化され、問題一覧に反映されます。
